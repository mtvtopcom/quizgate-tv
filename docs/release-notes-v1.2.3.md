# v1.2.3 — 应用内升级 + 崩溃自动熔断

> 答对再看 · 电视续时闸门。到点出一题，答对换 N 分钟。

这一版解决两个「用户会被卡死」的问题：**装的版本旧了没法自己更新**，以及**应用崩溃后无限重启闪屏**。

> 卸载 = 口令和设置丢失，需要重设。**从这一版起统一正式签名，以后再升级不用卸载。**

## 新增：应用内升级

每次进入应用都会查一次有没有新版（口令通过之后才查、才提示），有就弹升级页。**不强制**——点「以后再说」本次不再打扰，下次冷启动还会提醒。

升级分两步，装不装由你决定：

1. **点「立即更新」只下载**：下载 → SHA-256 → 包名 → 版本号 → 签名，四道校验过了才存进电视的「下载」目录（`Download/quizgate-x.y.z.apk`）。这一步不动系统、不弹任何窗
2. **点「立即安装」才装**：交给系统安装器，在系统那页按一次「继续更新」

几个刻意的设计：

- **包落在公共的「下载」目录**，家长能看到、能审计，知道自己装了什么
- **校验不过绝不交付**：下载中断、包被换、版本对不上，都会当场删掉并说明原因
- **签名不一致直接拦下**：否则系统会让你卸载重装，而卸载 = 口令、恢复码、计时设置全丢
- **进程被系统回收也不白下**：重进应用会从「下载」目录认出已下好的包，直接给「立即安装」
- **装不上有保底**：某些固件把安装器入口改过，拉不起来时包已经在硬盘上，用电视的「文件管理」打开即可

口令、恢复码、时长设置**不会**因为升级而改变。首次安装（或卸载重装）必须是家长自己设口令，安装包里没有默认口令。

## 新增：崩溃熔断

以前如果应用启动即崩溃，会陷入「闪屏—重启—再崩」的循环，只能靠卸载救。

现在连续 **3 次**守护服务崩溃后自动进入安全模式：不再自动启动，首页出现红色横幅，设置页「守护状态」里能看到崩溃原因并手动恢复。

判据是**真的崩了**而不是「启动过几次」——小米电视待机会强杀第三方应用，按启动次数算的话，按三次电源键就会误触发。所以只有守护服务存活期间发生的未捕获异常才计数；服务稳定运行 60 秒后计数清零。

## 修复

- **版本号注入此前是假的**：`aapt2 --version-code` 只在清单里没有该属性时生效，而清单写死了版本号，于是构建脚本里的版本号只影响文件名 —— 这正是「服务器清单说有新版、装上的还是旧版」那类事故的来源。现在构建前注入临时清单并断言
- 同名安装包会在「下载」目录里堆成 `quizgate-x.apk (1)(2)(3)`：落盘前先删同名记录
- 进程被回收后不认得已经下好的包：改为以磁盘为准

## 权限变化（请重点看）

这一版新增了两个权限，这是本项目第一次开口子：

| 权限 | 用途 |
| --- | --- |
| `INTERNET` | 只用于检查更新和下载安装包 |
| `REQUEST_INSTALL_PACKAGES` | 把下载好的包交给系统安装器（仍需人点「安装」，无法静默安装） |

可以审计的替代承诺：

- 全项目只有 `Updater.java` **两处** `openConnection()`，CI 会断言这个数量不变
- 请求是裸 GET，不带参数、不带 cookie、不上报设备信息，UA 固定为 `QuizGate`
  （默认 UA 会把机型、系统版本报出去）
- **不配置升级源构建时，一个字节都不发**：`QUIZGATE_UPGRADE_BASE= ./build.sh release`
- 除升级外，行为没有任何变化：不采集、不上报、不读屏幕内容、不接管桌面
